### Findings

**1. `<` and `>` count as delimiters, so spacing now changes in the middle of expressions, and unevenly**

lib/matplotlib/_mathtext.py:2477

`_left_delims` contains `<` and `_right_delims` contains `>`, but both are also in `_relation_symbols`. Outside `\left`/`\right` they are relations, not brackets. Because of this, a spaced symbol next to `<` or `>` loses a space even in the middle of an expression:
- `$a<=b$` gets narrower but `$a>=b$` doesn't.
- `$a=>b$` gets narrower but `$a=<b$` doesn't.

This isn't a boundary case, and the API note doesn't describe it. On main all four widths are identical.

Repro (executed: main code vs PR code on the 3.11.2 wheel, path backend, dpi 72):
```python
from matplotlib.mathtext import MathTextParser
p = MathTextParser("path")
for s in [r"$a<=b$", r"$a>=b$", r"$a=>b$", r"$a=<b$"]:
    print(s, p.parse(s, dpi=72).width)
# main: 38 38 38 38
# PR:   36 38 36 38   (expected: all equal)
```
Fix: take the relations out of the boundary sets:
- left check: `{'', '{', *(self._left_delims - self._relation_symbols)}`
- right check: the same with `_right_delims`

Then add `$a<=b$` vs `$a>=b$` (or similar) to the test so this can't come back.

**2. The API change note is named after the issue, not the PR**

doc/api/next_api_changes/behavior/23315-AM.rst

The template (`00001-ABC.rst`) says to name the file with the PR number. Rename it to `32331-AM.rst`.

**3. Optional follow-ups, not blocking**

- `$(=)$` drops both spaces, but `$\left(=\right)$` drops only the left one. The `next_char` check sees `\` from `\right`, not `)`.
- A binary operator at the end of an expression, like `$a-$`, still gets a space on its left. TeX turns such an operator into an ordinary symbol with no space on either side.

Neither of these breaks anything that worked on main.
