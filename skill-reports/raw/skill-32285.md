This branch (`pr-32285`, two commits) changes the Qt figure-options dialog. When "(Re-)Generate automatic legend" is checked, it now rebuilds the legend with the old legend's settings, where before it fell back to defaults: location, `bbox_to_anchor`/transform, spacing, frame, colors, font, title, `mode`, alignment, shadow and fancybox. It also adds a test that drives `figure_edit` through a mocked `fedit`.

**What I ran:** the branch wouldn't build here, so I installed the released matplotlib 3.11.2 wheel in a scratch venv with PyQt6 and Xvfb (I also installed a few Qt/X system libraries). Its `figureoptions.py` is byte-identical to this branch's merge-base, so I swapped in the PR's version.

- I suspected a crash when `bbox_to_anchor` is a plain `Bbox` (e.g. `ax.get_window_extent()`). There isn't one: `Legend.set_bbox_to_anchor` (`lib/matplotlib/legend.py:1156`) always wraps its input in a `TransformedBbox`, so `._bbox`/`._transform` always exist.

## Findings

None of these block the PR.

**1. Some legend settings are still lost on regeneration (optional follow-up).**
`lib/matplotlib/backends/qt_editor/figureoptions.py:265`
These are still dropped: `handler_map`, the custom `shadow` dict, `labelcolor`, `markerfirst`, `reverse` and `scatteryoffsets`.
- **Easy to fix:** two of these are stored on the legend, so they cost one line each: `handler_map=old_legend._custom_handler_map`, and `shadow=old_legend._shadow_props if old_legend.shadow else False` in place of `shadow=old_legend.shadow`.
- **Not recoverable from the legend object:** `labelcolor`, `markerfirst` and `reverse`. `labelcolor="linecolor"` especially can't be rebuilt from the text colors, since the user may have just changed line colors in the dialog.

Fix: either add the two easy ones, or keep the scope and say in the PR description which settings are still reset.

Repro (executed; the mocked `fedit` simulates pressing OK with the regenerate box checked):
```python
from unittest import mock
import matplotlib
matplotlib.use("QtAgg")
import matplotlib.pyplot as plt
from matplotlib.backends.qt_editor import figureoptions
from matplotlib.legend_handler import HandlerLine2D
from matplotlib.lines import Line2D

def regenerate_legend(ax):
    def fake_fedit(datalist, **kwargs):
        vals = lambda form: [v[0] if isinstance(v, (list, tuple)) else v
                             for k, v in form if k is not None]
        general = vals(datalist[0][0])
        general[-1] = True
        payload = [general] + [[vals(c[0]) for c in s[0]] for s in datalist[1:]]
        kwargs["apply"](payload)
    with mock.patch.object(figureoptions._formlayout, "fedit", side_effect=fake_fedit):
        figureoptions.figure_edit(ax)

fig, ax = plt.subplots()
ax.plot([0, 1], color="red", label="a")
ax.legend(labelcolor="linecolor", handler_map={Line2D: HandlerLine2D(numpoints=3)},
          shadow={"color": "blue"})
regenerate_legend(ax)
new = ax.get_legend()
print(new.texts[0].get_color(), new._custom_handler_map, new._shadow_props)
```
- **Actual:** `black None {'ox': 2, 'oy': -2}`
- **Expected:** `red`, the custom handler map, and `{'color': 'blue', ...}`

**2. Leftover `ncols` handling.**
`lib/matplotlib/backends/qt_editor/figureoptions.py:296`
`ncols` is now read and used only inside the `if` branch. The `else` branch always calls `axes.legend(ncols=1)`, which is just the default. Fix: write `axes.legend()` in the `else` branch, drop the `ncols = 1` default at line 251, and pass `ncols=old_legend._ncols` inline.
