The branch moves the masked-value filtering in `cbook.boxplot_stats` ahead of the empty-data check, so a column where every value is masked now gets the NaN "empty" stats instead of reaching `np.percentile` with an empty array. It also adds a regression test for that case.

I couldn't run anything: `matplotlib` and `pytest` don't import in this environment, so everything below comes from reading the code. No PR thread was found for branch `pr-32515`, so I couldn't check for maintainer comments.

Points I checked:
- **The fix:** after the move (`lib/matplotlib/cbook.py:1285-1287`), the `len(x) == 0` check sees the data with masked values already removed. Nothing between the old and new positions used the unfiltered `x`, so the move has no other effect.
- **Does the test reach the new code?** Yes. `_reshape_2D` keeps the mask on a 1D masked array: it returns `[X]` without calling `np.asarray`. So the test's input arrives in `boxplot_stats` still fully masked.
- **Would the test fail on `main`?** Yes. On `main`, `len(x)` is 2, so the empty check is skipped. `x` then becomes empty and `np.percentile(x, [25, 50, 75])` raises `IndexError`.
- **Is the assertion meaningful?** Yes. Comparing against `boxplot_stats([])` key by key with `np.testing.assert_equal` treats NaN as equal to NaN and checks the empty `fliers` array, so it can fail.
- **Deprecation or API-change note:** not needed. This is a bugfix that turns a crash into the result empty input already produces.

Optional nit (not blocking): `lib/matplotlib/tests/test_cbook.py:185` covers only a 1D input. A 2D masked array where one column is fully masked and another is not would also cover the per-column path. That is the usual way this case comes up through `Axes.boxplot`.
