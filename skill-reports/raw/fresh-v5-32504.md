This branch adds a `pdflatex` case to `_get_executable_info` and makes the second half of `test_rcupdate` (the `pgf_rcupdate2` case) xfail when pdfTeX is newer than 1.40.26. It also regenerates the `pgf_rcupdate2.pdf` baseline image.

1. **The new baseline doesn't match the TeX versions CI runs** (`lib/matplotlib/tests/baseline_images/test_backend_pgf/pgf_rcupdate2.pdf`)
   - The old baseline's banner says it was made with pdfTeX `1.40.22 (TeX Live 2022/dev/Debian)`, the version on the ubuntu-22.04 runners. The new one was made with `1.40.26 (TeX Live 2024)` on a local dev build.
   - CI runs ubuntu-22.04 (1.40.22) and ubuntu-24.04 (TeX Live 2023, about 1.40.25). Both are ≤ 1.40.26, so they don't xfail and still compare against this file with `tol=0` (unless Ghostscript is old).
   - The branch both changes the baseline and xfails newer versions. Those two changes only make sense together if 1.40.22 and 1.40.26 render this figure identically, and nothing shows they do.
   - **Fix:** revert the baseline and rely on the xfail. Or, if the baseline really needed to change, say what changed visually and show it still passes on 1.40.22 and 1.40.25.

2. **Unreadable version strings make the test error instead of skipping** (`lib/matplotlib/tests/test_backend_pgf.py:161-162`)
   - The `needs_pgf_pdflatex` guard only checks that pdflatex works with pgf. It never parses the version.
   - So `_get_executable_info('pdflatex')` can raise `ExecutableNotFoundError` in the middle of the test whenever `-version` output doesn't match `pdfTeX .*-(\d+\.\d+\.\d+)`.
   - MiKTeX prints something like `MiKTeX-pdfTeX 4.x (MiKTeX 24.x)`, which probably doesn't match.
   - **Repro (not executed):** with MiKTeX, `pytest lib/matplotlib/tests/test_backend_pgf.py::test_rcupdate`. Actual: ERROR, "Failed to determine the version of pdflatex". Expected: pass, skip or xfail.
   - **Fix:** catch `ExecutableNotFoundError` and treat the version as unknown. Or use `subprocess` plus a regex locally in the test, rather than adding a public-ish branch to `_get_executable_info`.

3. **No reason given for the cutoff** (`lib/matplotlib/tests/test_backend_pgf.py:163-164`)
   - The xfail hides a rendering difference without saying what it is. Is it a pdfTeX change or a matplotlib bug? Is there an issue to link?
   - The imperative `pytest.xfail` also stops the test at that point and can never report XPASS, so nobody will notice once it's fixed.
   - **Fix:** link an issue in the reason. Ideally split the two rc sets into parametrized cases and use `pytest.mark.xfail(condition, reason=..., strict=False)` on the pdflatex case.

4. **Nit: docstring not updated** (`lib/matplotlib/__init__.py:377`). The `_get_executable_info` docstring lists the supported names and doesn't include the new `"pdflatex"`.
