The branch (`pr-32285`) changes the Qt figure-options dialog. When you tick "(Re-)Generate automatic legend", it now copies the old legend's settings onto the new one: location, `bbox_to_anchor`, spacing, title, frame, colours, font and so on. On `main` only `ncols` and draggability survive. The branch is current with `origin/main` and has no uncommitted changes.

### Findings

**1. A transparent legend (`facecolor='none'`) comes back with a black background (regression).**
`lib/matplotlib/backends/qt_editor/figureoptions.py:290`

The new code reads the old legend's colours back with `legendPatch.get_facecolor()` and `get_edgecolor()`, then passes the patch's alpha back in as `framealpha`. The colour getters return the colour after alpha has been applied:

- For `'none'`, `_to_rgba_no_colorcycle` ignores alpha and returns `(0, 0, 0, 0)` (`colors.py:369`, `:378`), so that is what the getter gives back.
- The old patch's alpha is `rcParams["legend.framealpha"]`, which is 0.8 (`legend.py:557`).
- The new legend gets `facecolor=(0, 0, 0, 0)` with `framealpha=0.8`. `Patch._set_facecolor` calls `to_rgba(color, alpha)` (`patches.py:396-399`), which forces alpha to 0.8 on the tuple.
- Result: an opaque black box behind black label text.

`edgecolor='none'` breaks the same way and becomes a black border. On `main`, regenerating the legend also loses `'none'`, but it falls back to the default white frame, so the legend stays readable. This branch makes the result worse.

Repro (not executed; traced through the code above):
```python
fig, ax = plt.subplots(); ax.plot([0, 1], label="a")
ax.legend(facecolor="none", edgecolor="none")
# open Figure options, tick "(Re-)Generate automatic legend", OK
ax.get_legend().legendPatch.get_facecolor()
# expected (0, 0, 0, 0); this branch gives (0, 0, 0, 0.8): black box
```

**Fix:** pass the colours as they were originally specified, before alpha was applied: `old_legend.legendPatch._original_facecolor` and `_original_edgecolor`. That keeps `'none'` and lets `framealpha` apply exactly once. Add a `facecolor="none"` case to `test_figureoptions_preserves_legend_settings` that asserts the regenerated face alpha is still 0. The current test only uses default colours, so it can't catch this.

There's nothing else blocking. The `bbox_to_anchor` handling is correct: `set_bbox_to_anchor` re-wraps the inner `Bbox` with the same `BboxTransformTo(axes.bbox)` (`legend.py:1140-1157`). The new test also fails on `main` as a bugfix test should, since `main` drops everything except `ncols`.
